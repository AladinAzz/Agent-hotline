# phone calls (ringback)
- The `ringback-voice` MCP server can phone the user and hold a live voice conversation.
- Standing order: whenever you need any user input or have any question for the user, call them through `phone-caller` instead of asking in chat. Also call when you finish your work. If the call is not answered (`[NO ANSWER]`), do not retry; ask the same question in chat and continue. On a finish call, walk them through the details: what you did, what changed, what is still open, anything risky.
- Make every call through the `phone-caller` subagent (it runs on Haiku for fast replies). Do not use the ringback tools from the main model.
- Before each call, write a `context.md` at `~/.claude/phone/<project-name>/context.md` (overwrite any old one; never put it inside the project repo). Contents: project name and path; the goal; what was done so far; the current state; open issues and risks; the key files; why you are calling; the details to report; and each decision needed, with options and your recommendation. Pass the file path to `phone-caller` in your brief and say whether this is an input call or a finish call.
- `phone-caller` does not see this conversation. It reads `context.md`, has all tools, but only reads during the call; you carry out any changes the user asks for afterwards. It says the project name at the start of the call and returns what the user said.
- Do NOT call for tool permission prompts: those are approval dialogs in the app and cannot be answered by phone. Everything else you would ask the user, ask by phone. Keep spoken text in short, plain sentences and pause for questions; send logs or code as text, not speech.
